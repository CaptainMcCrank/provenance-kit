# Provenance Discover

**Purpose:** Walk a project's `.build-provenance/` tree and emit a single human-facing `PROVENANCE.md` digest at the project root — answering "what is this project, which prompts built it, at which versions, and what did they produce?" by inspection alone (use case D).

**Integration:** Anyone inspecting an unfamiliar project should reference this file:
> "Read and follow `prompts/Provenance_Discover.md` to generate this project's PROVENANCE.md."

**Prerequisites:** At least one session directory under `.build-provenance/`. Runs read-only; never modifies session data.

**Related:** [`Provenance_Verify.md`](Provenance_Verify.md), [`Provenance_Compare.md`](Provenance_Compare.md), [`README.md`](README.md)

---

## The three views (discoverability principle)

Provenance is presented at increasing depth so a reader never has to grep to answer a basic question:

1. **`PROVENANCE.md`** (this prompt's output) — one page: what the project is and a timeline of every build session.
2. **`summary.json`** (per session) — pre-rolled aggregates: totals and per-agent counters.
3. **`audit.yaml`** (per session) — append-only ground truth, for anything the summary can't answer.

`PROVENANCE.md` links down into views 2 and 3 so each claim is one drill-down from its evidence.

## Steps

### 1. Enumerate sessions

```bash
set -euo pipefail
ls -d .build-provenance/session_* 2>/dev/null | sort
```

For each session, read `manifest.yaml` (identity) and `summary.json` (aggregates). If a session has no `attestation.yaml`, mark it **unattested** (likely in-progress or abandoned) — do not hide it; an unattested session is itself a finding.

### 2. Run a lightweight verification pass

For each session, run [`Provenance_Verify.md`](Provenance_Verify.md) at `standard` level and capture the verdict. `PROVENANCE.md` shows each session's verification badge (`PASS` / `FAIL` / `unattested`) so a reader sees integrity at a glance, not just claims.

### 3. Emit `PROVENANCE.md`

Write the project-root `PROVENANCE.md` with the structure below.

```markdown
# Provenance

_Generated by `prompts/Provenance_Discover.md`. Read-only digest of `.build-provenance/`._

## This project
- **Project commit (latest attested):** <sha>
- **Prompt library:** <remote> @ <commit_short>
- **Sessions recorded:** <n>  (attested: <a>, unattested: <u>)

## Session timeline

| Session | Started | Harness | Prompts run | Artifacts | Tokens | Net | Verify |
|---------|---------|---------|-------------|-----------|--------|-----|--------|
| [`<short-uuid>`](.build-provenance/session_<uuid>/) | <date> | claude-code | 7 | 12 | 142k | 0 | ✅ PASS |
| [`<short-uuid>`](.build-provenance/session_<uuid>/) | <date> | opencode   | 5 | 6  | 89k  | 4 ⚠ | ✅ PASS |

## Per-session detail

### Session <short-uuid>  ·  ✅ PASS
- **Invoked from:** `<invocation_cwd>`  ·  **Harness session:** `<harness.session_id>`
- **Starting prompt:** `<path>` @ `sha256:<short>`
- **Initial request:** "<first ~120 chars of initial_user_message>…"
- **Library commit:** `<lib_commit>`  ·  **Final project commit:** `<project_final_commit>`
- **Attestation:** `<attestation_hash_short>` signed by `<signer_key_id>`
- **Prompts (in order):**
  | seq | agent | prompt_file | sha256 | writes | tokens |
  |-----|-------|-------------|--------|--------|--------|
  | 1 | initialization-agent-v1.0 | agents/init.md | `<short>` | 3 | 12k |
  | … |
- **Drill down:** [`summary.json`](.build-provenance/session_<uuid>/summary.json) · [`audit.yaml`](.build-provenance/session_<uuid>/audit.yaml) · [`attestation.yaml`](.build-provenance/session_<uuid>/attestation.yaml)

## How to verify any of this yourself
\`\`\`bash
# Re-run full verification on a session:
#   read prompts/Provenance_Verify.md  (level: full)
gpg --verify .build-provenance/session_<uuid>/attestation.asc \
            .build-provenance/session_<uuid>/attestation.yaml
\`\`\`
```

### 4. Surface anything noteworthy

In a short "Flags" section at the top of `PROVENANCE.md`, call out, when present:

- any session with `network_calls > 0` (and which agent made them);
- any `FAIL` verification verdict;
- any unattested session;
- any counter discrepancy reported by Verify;
- any prompt that drifted from its recorded hash.

Silence here should mean "clean," so never omit a real flag to make the page look tidy.

## Output

A single `PROVENANCE.md` at the project root, regenerable at any time. It is a derived artifact — safe to overwrite, and it should be regenerated rather than hand-edited.
